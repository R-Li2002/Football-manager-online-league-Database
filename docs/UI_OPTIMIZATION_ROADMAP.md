# HEIGO 全站 UI/UX 整体优化路线

更新时间：2026-07-31  
当前基线版本：0.4.75

## 目标

将目前分散在首页、联赛概览、球队中心、数据统计、球员库、教练主页和联赛工作台中的界面改进，收束成一套统一、可验证、可持续维护的产品体验。

整体风格继续保持轻盈、现代、清晰，与现有浅色/夜间主题一致。优化不改变已验证的业务逻辑，并明确保持“球队中心（公开球队信息）”与“联赛工作台（有权限的业务操作）”两个产品概念相互独立。

## 全程原则

- 每个阶段独立完成、独立测试、独立升级版本，避免一次性大改难以回滚。
- 桌面端、390px 手机端、375px 小屏、768px 平板和手机横屏都纳入验收。
- URL 深链、浏览器返回、筛选状态、登录状态与权限边界不得因视觉重构失效。
- 重要数据优先完整可读，装饰不能挤占队名、球员名、比分和关键操作。
- 普通访客只看到必要状态；教练、工作人员和管理员按权限显示操作与详细待办。
- 新组件优先复用设计变量和公共状态，不继续堆叠不可追踪的页面级覆盖。

## 当前基线

- `static/app.css`：22,608 行，存在多轮追加式样式和覆盖，需渐进模块化。
- 主导航和操作区混用字符图标、CSS 图标与 SVG，跨平台字形不一致。
- 多处辅助文字低于 `0.75rem`，小屏和低质量显示器下辨识度不足。
- 已有移动端底部导航、积分榜紧凑行、球队目录折叠等良好基础，应保留并扩展。
- 已有前端静态回归测试和 Playwright 验证流程，可扩展为全站视觉基线。

## Phase 0：基线、清单与防回归

范围：全站，只做审计与测试基础，不大规模改变界面。

工作项：

- 建立页面/弹窗/关键状态清单：空数据、加载、失败、无权限、已登录、编辑中。
- 保存浅色和夜间主题的桌面、390px、375px、768px关键页面截图。
- 记录横向溢出、过小文字、过小触控、字符图标、重复组件和 CSS 高耦合点。
- 扩展 UI coherence 测试，约束触控尺寸、精确 transition、动态视口和 reduced motion。
- 建立每阶段“自动测试 + Playwright 截图 + 健康检查”的固定发布模板。

完成标准：

- 核心页面和关键登录状态均有基线。
- 后续阶段每项改动能对应到页面、组件、验收项和测试。
- 不覆盖或清理当前工作树中与 UI 无关的既有改动。

## Phase 1：公共设计系统（已完成）

范围：字体、颜色、字号、间距、圆角、阴影、图标、按钮、表单、反馈。

工作项：

- 建立语义化设计变量：背景/表面/文字/边框/状态色、4–32px 间距、控件和卡片圆角、三档阴影。
- 自托管并精简中文 UI 字体，提供可靠系统字体 fallback，避免方框和跨平台字宽漂移。
- 建立正文、辅助文字、数据、标题的字号阶梯；常规可读文字原则上不低于 12px。
- 将 `⌂、⌕、＋、⇩、◉、⋯` 等字符图标逐步替换为统一线性 SVG。
- 统一按钮、输入框、选择器、胶囊、tab 的 hover、focus、pressed、disabled、loading 状态。
- 统一成功、失败、警告、空状态、骨架、重试和自动保存反馈。
- 新增 `prefers-reduced-motion` 全局降级规则。

完成标准：

- 主导航和全局操作区不再依赖平台字符图标。
- 移动端主要触控区不小于 44px；键盘焦点清晰可见。
- 浅色/夜间主题的对比度、阴影层级和交互状态一致。
- 新页面组件可以只使用公共变量完成基础视觉。

## Phase 2：首页首屏与信息优先级（已完成）

范围：首页宣传、搜索、MY CLUB、今日联赛、争冠形势、入口卡片。

工作项：

- 普通公告改为紧凑播报条；重大公告、冠军宣传和弹窗宣传保留高视觉级别。
- 压缩搜索区高度，保持全站搜索和高级搜索入口明确。
- 登录后优先展示关联球队队徽、下一场比赛、最近赛果和球队中心入口。
- 手机首屏直接露出今日联赛，减少卡片套卡片和无效留白。
- 今日联赛、争冠形势和级别标识统一视觉语法，球队位置优先显示队徽。
- 所有宣传按钮支持受控站内跳转，并保留安全的目标白名单。

完成标准：

- 390×844 首屏无需滚动即可看到搜索和至少一组今日联赛信息。
- 登录用户可在一次点击内进入关联球队。
- 普通公告不会长期占据大面积首屏。

## Phase 6：教练体系与联赛工作台

范围：教练登录、个人信息菜单、QQ 绑定、密码修改、教练主页、联赛工作台。

工作项：

- 登录后右上角统一显示头像、教练名、关联球队、个人主页、安全设置和退出入口。
- 首次登录强制完成默认密码修改和 QQ 绑定，流程不可跳过，并提供清晰进度及错误恢复。
- 教练主页编辑器提供草稿、已保存/保存中/保存失败状态和离开提醒。
- 联赛工作台按比赛与赛程、纪律与伤停、导入、宣传、队徽、账户权限、系统维护分组。
- 工作台危险操作与日常编辑分离，提供确认、操作结果、撤销可能性和审计入口。
- 宣传编辑、图片本地上传、队徽多来源匹配保持一致的后台工具反馈。

完成标准：

- 教练身份相关入口在桌面和手机端一致可见，不退化成含义不明的单图案按钮。

- 工作台始终以“有权限的业务操作”为定位，不与公开球队中心合并。

## Phase 7：性能、无障碍与工程收口

范围：资源加载、长列表、图片、CSS 结构、可访问性和全站回归。

工作项：

- 非当前 tab 的模块延迟加载，避免首页加载所有页面逻辑。
- 图片声明宽高、使用懒加载和稳定 fallback，减少布局跳动及 404 噪音。
- 大列表减少整页 DOM 重绘，筛选输入进行合理防抖。
- 将 `app.css` 按 tokens/shell/components/pages/responsive 分阶段拆分，保持加载顺序明确。
- 检查标题层级、ARIA、键盘导航、焦点圈、颜色对比度和屏幕阅读器名称。
- 加载超过约 300ms 时提供骨架或明确进度；失败提供原因与重试。
- 执行桌面、375/390px、平板、横屏、浅色/夜间的完整截图回归。

完成标准：

- 核心页面无 body 级横向溢出、无关键资源 404、无严重控制台错误。
- 键盘可完成主要导航、筛选、登录和保存操作。
- CSS 分层后不依赖末尾大范围覆盖维持正确外观。
- 全套前端测试、后端相关测试、健康检查和视觉验收通过。

## 阶段发布模板

每个阶段按以下顺序交付：

1. 明确本阶段页面、组件和不改动范围。
2. 保存改动前基线截图。
3. 实施小批次改动并补充静态/业务测试。
4. 运行相关 Node/Python 测试。
5. 使用 Playwright 验证桌面、390px 和夜间主题。
6. 检查 `/health`、浏览器 console、网络失败和布局溢出。
7. 更新 `VERSION`、`CHANGELOG.md` 和项目手册。
8. 独立提交与部署；发现回归时只回退当前阶段。

## 优先级

第一优先级：公共设计系统、首页首屏、数据统计导航与移动数据页。  
第二优先级：球队中心、联赛概览、球员库与详情。  
第三优先级：教练编辑体验、工作台反馈、CSS 模块化与深度性能治理。

该顺序先解决全站重复出现的问题，再处理页面专项，能以最少回归风险获得最大的整体改善。
