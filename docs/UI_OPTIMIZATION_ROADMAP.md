# HEIGO 全站 UI/UX 整体优化路线

更新时间：2026-07-31  
当前基线版本：0.4.102

## 目标

将目前分散在首页、联赛概览、球队中心、数据统计、球员库、教练主页和联赛工作台中的界面改进，收束成一套统一、可验证、可持续维护的产品体验。

整体风格继续保持轻盈、现代、清晰，与现有浅色/夜间主题一致。优化不改变已验证的业务逻辑，并明确保持“球队中心（公开球队信息）”与“联赛工作台（有权限的业务操作）”两个产品概念相互独立。

## 全程原则

- 每个阶段独立完成、独立测试、独立升级版本，避免一次性大改难以回滚。
- 桌面端、390px 手机端、375px 小屏、768px 平板和手机横屏都纳入验收。
- URL 深链、浏览器返回、筛选状态、登录状态与权限边界不得因视觉重构失效。
- 重要数据优先完整可读，装饰不能挤占队名、球员名、比分和关键操作。
- 普通访客只看到必要状态；教练、工作人员和管理员按权限显示操作与详细待办。
- 新组件优先复用设计变量和公共状态，不继续堆叠不可追踪的页面级覆盖。

## 当前基线

- `static/app.css`：球员库与球员详情批次完成后为 9,245 行；公共外壳、赛事、球队与球员库页面已有独立所有权，后续继续拆分教练、工作台、首页与公共组件残留。
- 主导航和操作区混用字符图标、CSS 图标与 SVG，跨平台字形不一致。
- 多处辅助文字低于 `0.75rem`，小屏和低质量显示器下辨识度不足。
- 已有移动端底部导航、积分榜紧凑行、球队目录折叠等良好基础，应保留并扩展。
- 已有前端静态回归测试和 Playwright 验证流程，可扩展为全站视觉基线。

## Phase 0：基线、清单与防回归

范围：全站，只做审计与测试基础，不大规模改变界面。

工作项：

- 建立页面/弹窗/关键状态清单：空数据、加载、失败、无权限、已登录、编辑中。
- 保存浅色和夜间主题的桌面、390px、375px、768px关键页面截图。

- 扩展 UI coherence 测试，约束触控尺寸、精确 transition、动态视口和 reduced motion。
- 建立每阶段“自动测试 + Playwright 截图 + 健康检查”的固定发布模板。

完成标准：

- 核心页面和关键登录状态均有基线。
- 后续阶段每项改动能对应到页面、组件、验收项和测试。
- 不覆盖或清理当前工作树中与 UI 无关的既有改动。

## 阶段发布模板

每个阶段按以下顺序交付：

8. 独立提交与部署；发现回归时只回退当前阶段。

## 优先级

第一优先级：公共设计系统、首页首屏、数据统计导航与移动数据页。  
第二优先级：球队中心、联赛概览、球员库与详情。  
第三优先级：教练编辑体验、工作台反馈、CSS 模块化与深度性能治理。

该顺序先解决全站重复出现的问题，再处理页面专项，能以最少回归风险获得最大的整体改善。
